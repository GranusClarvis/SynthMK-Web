Where SynthMK fits — and where it doesn't

Written by the SynthMK project, last reviewed June 2026. Vendors change their products and pricing; every section links the primary source so you can verify the current state yourself. Where a competitor is the better fit, this page says so.

The main event

vs Checkmk Synthetic Monitoring (Robotmk)

Checkmk's official synthetic monitoring is a commercial add-on built on Robot Framework via Robotmk. It is a serious, supported product — and it is aimed at organizations a tier above the teams SynthMK serves. The differences below are structural, not cosmetic.

Checkmk Synthetic Monitoring (Robotmk)SynthMK
Licensing Requires a commercial Checkmk edition, plus a separate synthetic-monitoring subscription licensed per test — see checkmk.com for current terms MIT license. Runs on Checkmk Raw (free) and commercial editions alike. No per-test, per-run or per-seat fees — it is open source
Authoring model Robot Framework keyword suites (.robot files) written by hand; typically a test-automation skillset Record in the browser, import a Chrome DevTools recording, click together in the visual builder, or write YAML — Playwright Python for the cases that need code
Probe environment RCC builds Python environments on each test host; environment management is the most common operational complaint in community forums One pre-baked Docker image with pinned Playwright and browsers. Nothing is built on the probe, ever
Credentials Secrets passed as environment variables, stored in agent configuration chmod-600 secrets file on the node, refused if readable by others; values redacted from all output and masked in screenshots; TOTP support for MFA accounts
Per-step visibility Rich: keywords can surface as their own services with their own thresholds Per-step metrics, graphs and a step breakdown on every service — one service per journey, steps as metrics
Failure artifacts Robot Framework HTML logs attached to results (commercial editions) Failure screenshots served from the node behind per-file HMAC tokens, linked from the service
Check management Agent Bakery rules; suite changes are file deployments Node dashboard: lint-gated editor, run-now, pause/resume, tags, version history with rollback, audit log — plus Setup-ruleset thresholds in Checkmk itself
Footprint A platform: scheduler agent plugin, RCC, suite repositories, bakery configuration One container, one MKP, one optional browser extension

Choose Robotmk when…

You already run a commercial Checkmk edition and want vendor support with an SLA. Your team already writes Robot Framework and owns suite libraries. You need keyword-level service granularity, bakery-managed fleet deployment, or RF's ecosystem beyond the browser (desktop automation, API keyword libraries). Those are real advantages and SynthMK does not pretend to replace them.

Choose SynthMK when…

You run Checkmk Raw and "is the login flow working?" should not require a procurement cycle. Your checks are authored by the people who own the applications, not a test-automation team. You want the probe to be one auditable container, credentials to be provably redacted, and the whole thing reviewable on GitHub before you deploy it.

The wider field

Other tools you may be evaluating

Different lanes, honestly framed. SynthMK's lane: self-hosted, Checkmk-native, no per-run pricing.

Datadog Synthetic Monitoring

A polished SaaS with browser tests, global locations and deep APM correlation — priced per test run, with results living in Datadog's cloud. If your monitoring estate is Datadog, use it. If your estate is Checkmk and your apps are internal, SynthMK keeps journeys, credentials and screenshots inside your network, alerts through the Checkmk pipeline you already operate, and costs nothing per run.

Checkly

Checkly defines the state of the art for Playwright-as-code monitoring — monitoring-as-code workflows, excellent developer experience, SaaS control plane with usage-based pricing. SynthMK borrows its best idea (Playwright underneath, code as the escape hatch) but inverts the control plane: Checkmk is the scheduler-of-record and UI, everything runs on your hardware, and the default authoring path needs no code at all.

Grafana Synthetic Monitoring

Grafana's offering (k6-based) is a Grafana Cloud feature: convenient if you live in that ecosystem, but the control plane is theirs and usage is metered. SynthMK is the equivalent capability for Checkmk shops — native services and graphs in the tool your NOC already watches, fully self-hosted.

Uptime Kuma

Uptime Kuma proves the demand for simple self-hosted monitoring — it is excellent at "is it up?" pings and status pages. It does not do multi-step browser journeys (log in, add to cart, assert the result), and it brings its own alerting stack. SynthMK starts where Kuma stops: real user journeys, reported into Checkmk's alerting, graphing and escalation instead of a parallel system.

How to verify this page: every claim about SynthMK links to public code or test evidence in the repository; every claim about another product links to that vendor's own page. If anything here is out of date, open an issue and it will be corrected.
